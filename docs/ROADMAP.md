# 路线图 / Roadmap

TriOffice 的目标不是复刻 Office，而是**在「够用」的范围内做到透明、可靠、零负担**。
下面按优先级排列待办，欢迎认领 —— 想做什么直接在 issue 里说一声。

## 0.2 —— 打磨现有三件套

- [ ] **表格**：条件格式（数据条 / 色阶 / 图标集）、数据验证（下拉列表）、筛选器、分列
- [ ] **表格**：更多函数（`XMATCH`、`LET`、`LAMBDA`、`TEXTSPLIT`、`REGEXEXTRACT`），补齐 `$` 引用在填充时的相对/绝对矩阵
- [ ] **表格**：把图表一并写入 XLSX（DrawingML），支持散点图与组合图
- [ ] **文档**：高亮备注 / 批注、目录（TOC）自动生成、图片对齐与环绕方式
- [ ] **演示**：元素旋转、成组、动画顺序、演讲者视图（备注 + 计时）
- [ ] **通用**：拖拽文件到工作台导入、只读分享链接（URL 内嵌压缩数据）

## 0.3 —— 一致性与可访问性

- [ ] 表格公式栏的自动补全与函数签名提示
- [ ] 完整键盘导航（可聚焦的工具栏、`role=grid` 语义、读屏软件支持）
- [ ] 高对比度主题、`prefers-reduced-motion` 支持
- [ ] 打印分页（`@page` 与分页控制）与页边距设置

## 0.4 —— 工程化

- [ ] 浏览器端端到端测试（Playwright）纳入 CI
- [ ] `types/index.d.ts` 类型声明，方便二次开发
- [ ] 可选导入 `.docx` / `.xlsx` 的“只读预览”模式（尽力而为，明确标注保真度）
- [ ] 插件机制：允许第三方注册函数、导出器与侧边栏面板

## 长期想法（未排期）

- 协作编辑（CRDT）—— 需要后端，与「纯本地」定位冲突，可能做成可选插件
- PWA 离线安装与文件系统访问（File System Access API）直接开写本地 `.trio`
- 移动端触控优化（软键盘、长按菜单、手势选区）

## 明确不做

- ❌ 宏 / VBA 兼容
- ❌ 二进制 OOXML 的完整双向读写（`docx` / `pptx`）
- ❌ 服务端渲染、云盘同步、账号体系
- ❌ 任何形式的埋点与遥测
